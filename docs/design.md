# HuxerUI Lib-AgentKit 设计方案

Lib-AgentKit 是独立发布的 C++20 库。它提供可组合的 HuxerUI 对话界面，以及可配置的 Agent 执行引擎。Agent 在 HuxerUI 宿主应用进程内执行。应用可以使用现成的对话页或自定义业务界面，并注册模型、工具和 Skill，让库驱动完整任务。PPT、代码、设计等专用助手和通用助手共享同一套会话、交互和执行机制。

库需要把一次任务从头走通。用户可以边看流式回复边阅读历史，Agent 可以在消息中询问、等待选择或请求授权，用户提交后原任务继续执行。执行期间可以委派子任务，也可以创建、分叉和联络独立会话。会话可围绕持续目标推进项目任务，并通过授权共享上下文和产物。结果可以是文字、数据或有明确权限的文件。界面和模型服务可独立替换，模型既可在本地运行，也可通过提供商接口调用云端服务。

同一个 AgentKit Preview App 提供代码、PPT、设计和通用助手。代码助手与 PPT 助手保留各自的基础端到端验收。完整版用「设计 → 实现 → 验证 → 做 PPT」验收主对话内的跨领域编排、独立会话协作和产物交付，再验收回撤、分叉方案审阅和按来源局部返工。

## 库与应用的接入方式

| 使用方式 | 应用提供 | AgentKit 提供 |
| --- | --- | --- |
| 使用默认对话页 | Agent 定义、模型适配器、工具与权限策略 | `AgentChat`、流式消息、表单和确认交互，本地 Agent 执行 |
| 仅使用本地执行引擎 | Agent 定义、模型适配器、工具与权限策略，自行处理交互 | 模型轮次、工具执行、暂停恢复和子任务调度 |
| 把 Agent 嵌入现有业务界面 | 自己的页面和业务控件，按需组合库组件 | 会话与执行接口、可单独嵌入的消息和产物组件 |

三种接法都从 `Conversation` 读取会话并向本地执行引擎发送命令。使用自定义界面的应用可以围绕同一个 `Conversation` 组合输入栏、消息列表或审批卡。

执行规则、事件归约和会话快照使用普通 C++ 值，可以独立做确定性测试。面向 HuxerUI 的异步接口复用 `Task`。应用级会话和本地引擎由宿主持有，可通过应用服务共享给多个窗口。视图挂载只绑定观察和本地输入，离开聊天页后同一个应用内的任务仍可继续。HuxerUI 的应用级任务作用域随 Runtime 结束。应用挂起期间的执行受平台生命周期约束。持久模式可在同一设备重新读取会话和协作状态，并按检查点恢复符合条件的 Run。 [HuxerUI 应用服务](https://github.com/HuxerUI/HuxerUI/blob/main/include/huxerui/app.h) · [应用级任务作用域](https://github.com/HuxerUI/HuxerUI/blob/main/include/huxerui/task.h)

### AgentKit 与宿主的职责

| 能力 | AgentKit 提供 | 宿主实现或配置 |
| --- | --- | --- |
| 会话与执行 | 会话快照和事件、模型轮次、Run 状态、预算、取消和交互恢复 | 持有应用级执行引擎，配置 Agent 定义、模型接入、用户身份和业务阶段 |
| 上下文与模型 | 定义轮次、增量事件、调用结果和续轮状态边界，按预算装配获授权输入 | 选择提供商、模型、协议和端点，接入适配器与凭据，按接收方过滤上下文 |
| Skill | 按权限发现元数据，激活指定版本，向 Run 提供流程指令和按需资源，记录恢复所需版本 | 注册来源，划定目录或包的信任范围，为可执行脚本接入受控工具 |
| 工具与审批 | 校验参数，登记工具计划、审查、人工确认和结果，按声明与冲突键调度 | 实现工具、权限、写入及跨 Run 资源协调，可为授权场景提供规则或模型审查器 |
| 交互与产物 | 默认对话和交互组件、消息块的数据及动作校验、产物引用和受控分发 | 注册业务组件类型、数据 schema、渲染器及动作，接入文件选择器、预览和存取 |
| 会话协作 | 会话发现、创建、分叉、收件箱、输入队列、回复关联及等待 | 配置会话可见性和收发策略，分配共享或独立的工作区 |
| 项目与目标 | 项目快照、任务依赖和领取，目标状态、证据与完成审核，共享项版本 | 定义项目成员和工作区、完成条件、验证器及是否需要用户确认，配置资料的发布和使用范围 |
| 变更与来源 | 回撤计划和结果记录、分叉比较状态、产物来源及影响查询、返工审批 | 提供工作区隔离、候选差异、资源版本和恢复能力，登记片段依赖并实现局部重生成 |
| 生命周期与存储 | 应用内会话和订阅、内存会话与日志事件，持久模式提供可插拔存储接口 | 提供存储位置、保留策略和日志接收方，核对工具无法确认的副作用 |

## 会话与执行模型

| 对象 | 语义 |
| --- | --- |
| `Session` | 一段可重新打开的对话，包含历史、来源、当前执行、输入队列、协作收件箱、待处理交互和产物引用。一个会话同一时间只有一个活动根 Run。不同会话可以并发执行。 |
| `Run` | 一次任务的执行记录。根 Run 可由用户输入、已受理的协作请求、项目任务或持续目标触发；子 Run 由父 Run 委派。等待和从本地检查点续跑沿用 `RunId`。重试或重新生成创建新 Run，并保留来源及原有结果。 |
| `Message` | 对话中的一条可见记录，有稳定 ID、作者和有序内容块。运行状态和工具记录可以投影到消息中，历史渲染使用已经记录的内容。 |
| `Interaction` | 一次待处理的结构化输入或授权请求，绑定会话、接收人、请求 ID 和版本。任务中的交互关联所属 Run；会话级的协作确认也可在空闲时处理。视图卸载或窗口切换时，交互由会话持有。 |
| `Artifact` | 模型或工具交付的文件或结构化结果，以版本化的受控引用挂到消息、Run 或项目任务上。工具结果和协作消息都可引用已有产物。 |
| `CollaborationMessage` | 带来源和目标的会话间消息，记录投递、关联请求及可选最终回复。界面可将其投影到会话历史和收件箱。 |
| `Goal` | 会话中的持续目标，包含完成条件、预算、阻塞原因及证据，可以跨多个 Run。 |
| `ProjectTask` | 项目中可分配、可依赖、可验收的工作项，由具体一个执行尝试关联实际 Run。 |

会话历史、模型上下文和审计记录分别有明确用途。界面保留用户看到的消息和可见产物。每次调用模型时，执行器按预算组装指令、必要的历史、选中的上下文和允许的工具结果。审计记录保存关键操作的身份、授权范围和结果状态，由宿主决定保留周期。模型摘要可作为后续上下文，原始记录仍按会话留存策略管理。需要跨会话记忆的应用通过上下文提供器显式接入存储，按用户和工作区限制检索与写入范围。

## C++ 公开接口

[API 设计稿](api-design.md)定义公共 C++ 类型、签名、状态和失败语义。宿主在 HuxerUI 应用级作用域持有一个 `AgentRuntime`，通过 `RuntimeOptions` 接入身份、权限策略、存储和产物服务。默认界面和自定义界面都通过同一运行时访问会话。 [Runtime 注册与宿主接入](api-design.md#runtime-注册与宿主接入)

| 对象 | 职责 |
| --- | --- |
| `AgentRuntime::Sessions()` | 返回 `SessionService`。通过 `CreateAsync` 创建会话，`OpenAsync` 按 `SessionId` 打开已有会话，`ForkAsync` 从已提交历史分叉。列表、列表订阅、历史分页和会话元数据修改也使用该服务。 |
| `Conversation` | 持有已打开会话的读写入口。通过 `Snapshot()` 读取不可变快照，由 `ObserveAsync` 订阅更新。提供发送、排队、调整、提交交互、取消、重试、重新生成和显式转交。多个窗口打开同一 `SessionId` 时共享会话状态。 |
| `AgentRuntime::Commands()` | 按命令 ID 或获准审阅的操作审批读取及订阅命令进度。审批后的命令结果保留与直接回执相同的类型。Run 和工具结果由各自状态投影确认。 |
| `AgentRuntime::Interactions()` | 按当前用户授权列出和订阅统一待办，处理时打开所属会话并提交原交互版本。 |
| `AgentChat` | 使用已打开的 `Conversation` 渲染默认对话界面。宿主也可用同一对象组合自己的消息、表单和审批组件。 |

`SessionService::CreateAsync` 支持创建空会话、提交首条用户输入或带初始协作任务创建。带首条用户输入时会话、消息及根 Run 一并提交；协作任务按接收策略确认、排队或启动。直接受理与审批后生效均通过 `SessionCreated` 取回可用的标识。 [创建和首条消息](api-design.md#创建和首条消息)

`InteractionReply` 携带交互 ID、预期版本及表单值、放弃表单或审批决定。执行器从已登记的交互取回所属会话、Run 和批准对象。命令、权限及 I/O 的预期失败通过 `AgentResult` 返回，字段错误带路径，冲突可带当前修订。 [Run、事件和交互](api-design.md#run事件和交互)

空闲会话通过 `SendAsync` 发送。运行中补充通过 `SteerAsync` 绑定指定的 Run，独立的下一项任务通过 `QueueAsync` 排在当前 Run 后。创建时的首条用户输入、空闲发送和用户排队可提交 `UserRunOptions`。补充在下一轮模型调用或工具调度的安全边界生效。影响旧计划时重新准备和审批，已开始的工具按原调用记录结果。用户提交时目标 Run 已结束，或受理后未能应用时，保留原输入并反馈实际状态，由用户明确选择另发或排队。 [运行中发送与补充](api-design.md#运行中发送与补充)

会话状态由 HuxerUI 应用线程提交，应用级任务作用域持有已接受的运行。后台 SDK 回调把拥有的数据交给应用线程，耗时工具由宿主安排到工作线程或服务上执行。视图卸载只解除观察。 [Task 和应用线程](https://github.com/HuxerUI/HuxerUI/blob/main/docs/design/tasks.md)

## 流式事件与恢复

每个会话有一条权威事件序列。本地执行器在提交时分配连续递增的序号。`SessionEvent` 携带会话 ID、序号、`CommitId` 和可选命令 ID。具体事件携带适用的 Run、消息块、工具或产物标识。跨会话提交通过同一个 `CommitId` 关联，项目更新有独立的修订。 [Run、事件和交互](api-design.md#run事件和交互)

- **观察与合并。** `ObserveAsync` 在同一提交边界登记观察并读取初始快照，随后交付不可变的新快照。观察可合并中间快照。模型流由适配器解码，正文和进度可按帧更新界面。访问撤销后观察以错误结束。重放时跳过已经应用的序号，遇到缺口从可信快照重建。 [HuxerUI 流式响应契约](https://github.com/HuxerUI/HuxerUI/blob/main/docs/guide/http.md) · [公共约定](api-design.md#公共约定)
- **提交去重。** 去重键由存储域、可信主体和 `CommandId` 组成。Agent 调用再绑定来源 Run。相同键和载荷返回原回执，载荷不同返回 `Conflict`。提交结果不明时通过 `Commands()` 查询并沿用原命令 ID。不同命令同时提交同一交互版本时，只有一次能消费。用户主动重试任务使用新命令。

### Run、交互与工具调用状态

Run 的状态为 `Running`、`WaitingForInput`、`WaitingForReply`、`WaitingForDependency`、`Cancelling`、`Succeeded`、`Failed`、`Cancelled`。若所有可继续的工作都受阻，同时有多种等待时，界面优先呈现 `WaitingForInput`，其后为 `WaitingForReply` 和 `WaitingForDependency`，快照记录各自的等待项。交互从 `Pending` 进入关闭状态，记录提交、批准、拒绝、过期、取消或失效原因。已关闭的交互版本保留在历史中，需要重新作答时发布新版本或新请求。视图关闭和重新打开只影响订阅。

| 条件 | 执行器行为 |
| --- | --- |
| 接受发送或重试 | 同一会话只接受一个活动根 Run，有活动 Run 时返回会话忙。新 Run 进入 `Running`。重试以已结束 Run 的原始用户输入创建新 Run，保留来源和历史，重新检查上下文和权限，重新走所需审批。原 Run 有待核对的写入时，先核对结果再允许重试。 |
| 发布表单或审批 | 先登记 `Pending` 交互，再发事件。当所有可继续执行的工作都在等待输入时，Run 进入 `WaitingForInput`。 |
| 当前版本收到有效回复 | 原子关闭该版本并把回复交给等待方。Run 内的交互可以继续时回到 `Running`，沿用原 `RunId`。工具批准开放对应调用，会话级确认更新对应消息或项目操作。拒绝按所属流程处理。 |
| 交互到期 | 执行器关闭仍处于 `Pending` 的请求，并将过期结果交给等待方。若提交时请求仍待处理但已过截止时间，先结清，再返回 `DeadlineExceeded`。 |
| 等待协作回复或已登记任务依赖 | 所有可继续的工作受阻时进入对应的等待状态。回复、上游结果、超时或取消以事件交给等待方，允许继续时恢复原 `RunId`。项目中尚未具备启动条件的任务在项目状态中等待。 |
| 回复字段非法、版本过旧或已处理 | 字段校验失败保留 `Pending` 并返回字段错误。旧版本返回 `Conflict`，已关闭返回 `AlreadyClosed`。 |
| 提交取消或达到 Run 时限 | 如果 Run 尚未终结，先进入 `Cancelling`，关闭待处理交互，停止新调度，通知活动的模型、工具和子 Run。活动调用均已收尾或达到取消收尾时限后，用户取消记为 `Cancelled`，Run 超时记为 `Failed` 并保留原因。 |
| 正常结束或执行失败 | 执行器按提交顺序写入唯一的 Run 终态。若完成先提交，后到的取消返回已结束。若取消先提交，Run 终态按取消路径确定，晚到的结果只更新调用记录。 |

取消与批准按执行器提交顺序处理。取消先提交时，审批以已关闭返回。批准先提交且工具还未调度时，取消终止调度。工具已启动时，通过取消信号通知宿主停止尚未开始的写入，并按实际副作用收尾。

工具调用单独记录准备、自动审查、等待用户确认、可调度、执行中和结果。结果区分完成、执行前拒绝或冲突、执行失败、部分完成、已证实未执行及结果待核对。执行器在应用级作用域登记工具结果。宿主在 Run 关闭后取得的结果由应用级引擎按调用 ID 补记。写入已发出且收尾时无法确认结果，或工具已启动但无法证明尚未写入时，将该调用标记为待核对。HuxerUI 取消会销毁挂起的协程，Run 所有者负责关闭交互和写入终态。 [HuxerUI Task 取消语义](https://github.com/HuxerUI/HuxerUI/blob/main/docs/design/tasks.md)

内存会话支持同一 Runtime 内关闭页面和重新打开。本地持久模式由 `SessionStore` 保存事件、快照、待处理交互和检查点。后端按预期存储修订原子提交记录，单个会话的顺序仍由自身序号表示。检查点设在工具调度前、结果确认后和等待输入等明确边界。自动续跑取决于该 Run 的检查点、当前授权及外部操作的核对结果。 [存储与恢复规则](api-design.md#持久化和恢复)

持久化格式使用独立版本和稳定的事件名称。扩展内容使用带命名空间和版本的类型标识。无法解释的执行或授权事件触发重新同步或版本错误。

### 协作数据的持久化与恢复

持久化保存会话来源、分叉边界、转交记录、会话输入队列及其启动配置、消息与收件箱、请求和最终回复、等待关系、目标定义历史、用量和绑定定义及证据版本的完成审核、任务依赖和领取状态、项目共享项版本、命令回执和所需检查点。临时旁聊及其执行状态保留在内存。用户在普通会话显式提交的旁聊结论与该消息或队列项一起保存，独立获准的产物按其自身的保留规则保存。每条会话有自己的事件序号，项目有自己的修订号。跨会话及项目操作用命令、消息或任务 ID 关联。

同一次本地事务提交消息状态、相关会话事件和收件箱记录，以及可查询的回执。工作请求的消费、队列更新及目标 Run 的登记也一次提交。最终回复与请求状态、唤醒所需的记录一同提交。持久模式的 `SessionStore` 需要覆盖这些记录的事务边界。提交结束后再通知观察者和调度器。重新打开存储时从已提交的记录重建状态，再检查权限、版本、期限和预算后恢复调度。恢复数据包含宿主阶段及版本、输入版本、等待截止时间、当前阶段的命令 ID 和关联请求或任务的稳定 ID。流式回调在新的操作实例上重新注册，宿主用登记的阶段恢复函数重建等待。无法恢复的 Run 以中断原因结束，用户可按重试规则重新开始。

目标和任务调度以已登记的版本和执行尝试去重。用量、领取及对应 Run 的登记与调度事件一起提交。重启后，已消费的消息回到原关联 Run 或保留该 Run 的中断状态，未消费的消息仍在队列。恢复等待时先读取已提交的回复或任务结果，已有结果时回到原 Run 对应阶段。未结清的等待按原截止时间恢复。审批过期、引用撤销、工作区变化和外部操作结果未知都按相应条件处理。宿主负责数据保留策略、索引清理和文件授权的重新取得。

## 对话与交互组件

`AgentChat` 提供当前会话的消息、输入及交互。宿主可以替换组件、使用自己的主题，或按需组合下列界面。会话目录使用 `Sessions()`，当前对话的状态和操作使用 `Conversation`。

| 组件 | 默认能力 |
| --- | --- |

### 消息块与用户输入

一条消息由有序块组成，块 ID 在增量更新和历史重放中保持稳定。消息列表、任务待办和宿主侧栏可引用同一条交互。模型通过声明过的交互工具发起请求，宿主编排也可以直接发起。执行器先验证请求并登记待处理状态，再发布事件。

`FormRequest` 携带字段约束、显示配置和可选的业务渲染类型及产物引用。首版表单覆盖单行和多行文本、布尔、数字、单选与多选。字段约束采用 JSON Schema 的对象、必填字段、标量类型、枚举、枚举数组和长度或数值范围。显示标签、字段顺序和控件偏好单独配置。字段值使用稳定键和枚举 ID。显示端可以做即时校验，执行端按同一约束再校验提交；超出首版约束的表单由宿主控件和验证器处理。 [JSON Schema 规范](https://json-schema.org/draft/2020-12)

草稿归会话界面或宿主管理，以交互 ID 和版本为键，寿命长于单个虚拟列表项。布局切换或重新挂载后可按原键恢复。字段错误保留同一版本的草稿，提交过时后可刷新到新版本供用户核对。两种界面都用 `SubmitAsync`，以执行器确认的交互状态为准。

宿主通过 `RegisterContentComponent` 注册带版本的组件类型、数据 schema、HuxerUI 渲染器及其可提交的动作。宿主可在助手指令中说明何时使用组件，模型经工具或结构化输出提供数据。AgentKit 按 Agent 定义及 schema 校验，保存可重开历史的 `CustomBlock`。缺少对应版本的渲染器时显示纯文本回退。

例如 App 注册饼图，模型提交分类和数值，图例筛选由组件本地处理。将某项提交给当前 Run 或回答导出表单时，由组件带消息版本与块 ID 发送登记的动作。运行时检查用户、动作 schema 和实际目标，复用输入、交互或产物操作及所需审批。多区域动态界面可选接入 A2UI，宿主负责其可用组件目录。 [自定义组件 API](api-design.md#自定义对话组件与动作) · [A2UI 组件目录](https://a2ui.org/concepts/catalogs/)

## 模型与 Agent 定义

`AgentDefinition` 是可复用的配置值，包含稳定 ID、指令、模型、可用工具和运行预算。定义可引用已注册的上下文提供器和宿主编排，并声明可用的会话协作、项目操作及可委派的 Agent。可用 Skill 由 `AgentDefinition::skill_sources` 声明。每次执行固定使用当时的定义版本和能力范围，工具调度仍按当前授权核对。应用可以提供配置值，也可以将自己的配置解析成已注册的名称。

### 第三方注册与策略

第三方应用链接 `HuxerUI::AgentKitRuntime` 或带默认视图的 `HuxerUI::AgentKit`，在应用级服务初始化时建立 `AgentRuntime`。用 `RegisterModel`、`RegisterContextProvider` 和 `RegisterTool` 登记模型、上下文和业务工具，可用 `RegisterToolCatalog` 登记动态目录，再用 `RegisterAgent` 组装一个专用或通用角色。注册使用带宿主命名空间的稳定 ID。工具定义携带版本、参数和输出 schema、效果、准备与执行处理器。Agent 定义以 ID 引用这些注册项，并声明协作对象及可用操作。注册时校验重复 ID 和定义格式。启用角色前统一校验注册项引用、协作对象和所需的模型能力，支持应用先登记相互协作的多个角色。宿主也可以把自己的配置文件解析为这些定义。

宿主用 `AgentRuntime::Create(RuntimeOptions)` 建立运行时。通过 `RegisterAgent` 登记 `AgentRegistration`，再用 `ValidateRegistration()` 校验引用关系，`StartAsync()` 成功后开放会话入口。注册使用 `ModelId`、`ContextProviderId` 等明确的 ID 类型。权限策略由 `RuntimeOptions` 接入，并由执行器在运行时调用。配置至少明确哪些主体和 Agent 能读哪些资源、能调用哪些工具、能发现或联系哪些会话、能否唤醒接收方，以及哪些目标需要用户确认。工具、协作和项目能力取定义声明、当前用户授权和宿主策略的交集。工具策略按实际参数、效果和目标返回允许、拒绝或要求用户确认。已准备的工具计划也可由策略交给宿主审查。接收侧独立检查自己的项目权限和资源版本。

启动后，宿主通过 `Sessions().CreateAsync` 提交会话选项，取得 `SessionCreated` 后通过 `Sessions().OpenAsync` 打开 `Conversation`，供 `AgentChat` 或子组件使用。运行时通过 `RegisterContentComponent` 登记组件的 schema 和动作。宿主根据可见消息和产物预览选择业务界面。新增领域可复用已有会话、审批、项目依赖和产物机制，通过新的工具、上下文、编排及渲染接入。

### 模型轮次与宿主编排

`ModelProvider` 声明能力并通过 `StartTurnAsync` 返回模型流，流通过 `ReadAsync` 读取模型事件。`AgentRegistration` 将 `AgentDefinition` 与可选的 `RunHandler` 和 `RunRestore` 绑定。`RunHandler` 接收 `RunContext` 和包含触发来源的 `RunInput`。`RunContext` 提供模型循环、提问、工具、子 Run 委派和检查点操作，也提供受当前 Run 约束的服务句柄。 [模型、上下文、工具和授权](api-design.md#模型上下文工具和授权) · [Runtime 注册与宿主接入](api-design.md#runtime-注册与宿主接入)

每项模型注册固定提供商、模型、协议和端点。GPT 的 Chat Completions 与 Responses、Claude Messages、Gemini Interactions 与 `generateContent`、DeepSeek 和智谱的多个端点各由适配器归一化。工具回传关联、能力缺失、流结束和取消按端点处理。提供商所需的续轮数据在授权后按原适配器和输入边界使用。本地会话拥有历史和工具结果，分叉或切换配置时按授权重新装配输入。 [协议与能力矩阵](api-design.md#提供商协议与能力) · [模型续轮](api-design.md#续轮分叉与恢复)

- `ModelTurnRequest` 包含指令、获授权的上下文、选用的历史、可调用的工具及前一轮工具结果。`ModelEvent` 覆盖文本增量、工具调用起止与参数增量、结构化结果、用量和轮次结束。轮次结束带有完成原因。流提前到达 EOF、I/O 出错或提供商报告截断时，该轮按不完整处理。适配器负责鉴权、提供商数据格式、流解码和能力声明。首版需要文本流和工具调用；结构化大纲可用提供商的结构化输出，或用带参数 schema 的工具提交。提供商托管的工具须有对应的宿主授权和可执行的审批路径，首版的业务工具统一在宿主执行。 [OpenAI Responses 流式事件](https://developers.openai.com/api/reference/resources/responses/streaming-events) · [Anthropic 流式消息](https://platform.claude.com/docs/en/build-with-claude/streaming)
- 执行器按调用 ID 收集参数分片，校验收到的起止边界。正常轮次结束后，才解析完整参数并按工具 schema 校验和调度。默认按调用声明顺序执行。完整版允许宿主显式声明可并行的工具，同一轮的结果按原调用 ID 和声明顺序带入下一轮。参数校验或策略失败也返回对应结果，模型可在预算内继续。轮次不完整时保留已显示内容，丢弃该轮待调度的调用，并向运行流程返回中断原因。
- 默认模型循环在模型正常结束时完成 Run，无法继续的轮次错误以失败结束。配置 `RunHandler` 时，宿主可通过 `CompleteAsync` 运行限定工具范围的模型循环，通过 `AskAsync` 等待用户，通过 `CallToolAsync` 调用已注册工具。阶段所需的工具由对应调用声明，执行器取其与 Agent 定义和当前授权的交集。模型发起和宿主发起的工具请求经过相同的参数校验、授权、记录和取消流程。Run 的终态由执行器根据流程完成、失败或取消写入。
- 跨会话的设计、实现、验证和交付依赖用项目任务 DAG 表达。在单个 Run 内，宿主用 `RunHandler` 编排条件分支、重试和委派，用 `RunRestore`、检查点及原交互和工具调用引用恢复阶段。需要独立发布、图形编辑或逐节点恢复的宿主，可再设计映射到现有入口的 Graph API。 [编排与调度契约](api-design.md#run-内编排与项目调度)
- 预算按模型轮数、工具次数、上下文大小和时限累计。进入下一轮或发起工具前检查相应预算，超限以明确原因结束。Run 时限从命令被接受起计算，交互还可设置自己的截止时间。提供商可用的用量单独累计，UI 展示宿主允许公开的部分。

### 上下文与引用

`ContextProvider` 接收当前会话、Run、用户选定的资源引用、模型接收方和上下文额度，返回已授权的内容快照。资源引用携带宿主能够解析的资源 ID、版本及可选位置，例如代码行范围或资料段落。宿主在读取时校验权限，决定使用磁盘内容还是编辑器中未保存的版本，并决定可以发给模型的内容。执行器按预算装配这些片段，记录实际用到的引用，界面据此交给宿主定位原文。跨会话记忆和检索索引可作为宿主提供的上下文来源。

## Tool、MCP 和 Skill

### Tool

工具注册项包含工具 ID、版本、面向模型的描述、参数 schema、可选输出 schema、效果与并行声明，以及准备和执行的异步处理器。效果声明区分读取、生成应用暂存产物、修改用户资源和向外部提交。宿主策略接收当前主体、调用来源、效果、范围和具体目标，返回 `Allow`、`Deny` 或 `RequireConfirmation`。

`ToolPrepare` 接收 `ToolPrepareContext` 和 `ToolRequest`，返回 `PreparedChange`。执行器登记不可变的 `PreparedToolCall`，再由 `ToolHandler` 接收执行阶段的 `ToolContext` 和该调用。 [工具定义与准备](api-design.md#工具定义与准备)

执行器校验参数并检查准备阶段的读权限。准备处理器取得目标、基线版本和可审阅的预览，执行器将其与已校验参数绑定到计划。触发审批时先登记预览产物，再发布交互。批准后重新核对权限和版本，通过后将原计划交给执行处理器。简单只读工具可由执行器按已验证的请求准备。

`ToolContext` 提供稳定的 `ToolCallId`、资源授权、进度上报、结构化提问及取消信号。宿主用 `ToolExecutionResult` 回报实际执行结果、已影响资源及待核对事项，并分开提供可送给模型的数据、界面内容块和产物引用。工具可登记实际写入的版本、用于回撤的受控记录以及产物和来源片段的依赖。开始执行后发生的业务失败或部分写入也经同一回报记录实际结果。执行器在无法取得结果时按已知的调度阶段标记失败或待核对。宿主可注册 SSH 访问或远端构建工具，本地 Run 使用相同的调用和审批流程。

AgentKit 将工具回报的产物草稿登记成版本化 `ArtifactRef`，与工具结果和产物来源一并提交。宿主通过 `WaitForToolAsync` 或 `CallToolAsync` 返回的 `ToolResult::published_artifacts` 直接取得新版本。结果供后续导出、回复及验证引用，重启后按原调用恢复相同版本。 [工具结果与产物交付](api-design.md#工具结果与产物交付)

宿主可明确允许只读或资源不冲突的调用在同一模型轮次并行，并配置并行上限。准备阶段给出覆盖读写范围的统一冲突键。共享资源的读写或写写冲突由执行器按调用顺序协调，范围未知的调用串行执行。执行器仍逐项核对权限、版本、审批和预算，宿主负责跨 Run 的资源协调和实际写入时的版本检查。 [同轮工具调度](api-design.md#同轮工具调度)

### MCP

MCP 客户端是可选适配器，按已实现的协议修订和能力接入服务器。宿主启动前登记工具目录，适配器按当前凭据和授权范围读取工具清单，收到列表变更通知后发布完整的新修订。AgentKit 原子更新目录，下一轮模型看到获准的最新工具。已经声明或排队的调用绑定原工具版本，准备、审批生效和执行前检查版本及权限。工具被移除或换版时结清旧调用和批准。固定注册项保持启动时的定义。资源读取和提示模板按宿主选择进入上下文。 [动态工具目录](api-design.md#动态工具目录) · [MCP Tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)

Streamable HTTP 用于远端连接。桌面可通过应用显式提供的进程宿主使用 stdio。连接身份、凭据、超时与取消由适配器维护。 [MCP Transports](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports)

支持 MCP elicitation 时，表单模式映射到当前工具调用的交互请求，表单提交、拒绝和取消映射回协议结果。需要凭据或 OAuth 的 URL 模式走宿主受控的浏览器或授权界面。适配器只声明已实现、可正确呈现和取消的能力，并为不同协议修订保留独立测试。 [MCP Elicitation](https://modelcontextprotocol.io/specification/2026-07-28/client/elicitation)

### Skill

Skill 为当前 Run 提供可选的流程指令和资料，例如验证代码变更或把验证报告整理成发布演示。宿主注册 `SkillSource`，选择打包资源、获准目录或应用管理的远端目录，并配置哪些 Agent 和工作区可用。来源按 Agent Skills 规范读取 `SKILL.md`，正文及资源用同一个 `SkillRef` 固定版本。目录只提供获准条目的名称、描述及供激活的引用。 [Skill API](api-design.md#skill-的来源激活和资源) · [Agent Skills 规范](https://agentskills.io/specification) · [Agent Skills 接入指南](https://agentskills.io/client-implementation/adding-skills-support)

用户可在发送时选用 Skill，模型可在本轮任务中主动激活，宿主编排也可以通过 `RunContext` 明确选择。运行时核对来源、版本和当前授权，按策略发起确认。获准的 `SKILL.md` 正文单独进入该 Run 的模型上下文，作为受宿主指令约束的流程指导。模板和引用按需从对应版本读取，宿主的来源实现限制访问范围，运行时复核每次资源访问。声明所需工具只用于说明，实际调用由宿主授权和审批。脚本使用已登记的工具执行，适用该工具的工作目录、时间及资源限制。

运行记录保留实际激活的版本、发起方式与资料来源。该 Run 的历史压缩保留活跃 Skill 指令，恢复时加载原版本并重查权限。更新的包进入下一次发现，已激活的 Run 使用所选版本。版本缺失或撤销时，运行时报告原因并停止需要该 Skill 的后续操作。子 Run 或独立会话在自己的权限范围内选择 Skill。

## 子 Agent、多 Agent 与专家团

父 Run 通过一个委派入口提交一个或多个子任务。任务携带 Agent ID、任务说明、显式上下文和预期结果。每个子 Run 有独立的 `RunId`、模型轮次、工具记录、预算份额和取消状态，向父 Run 返回结构化结果或产物。父任务可由模型选择委派，也可由应用的编排回调决定顺序。两者共用同一个 `DelegateAsync` 入口与策略。批量调用由执行器按并行预算调度，返回与输入顺序对应的逐项结果。

- **串行委派。** 主 Agent 把边界明确的任务交给一个专长 Agent，例如让资料整理 Agent 提取背景和引用，再用结果生成大纲。
- **并行专家团。** 协调者同时委派多个角色，按任务关联展示进度。各子任务只收到指定上下文。汇总由协调者完成，按应用声明处理部分失败和选用结果。只有宿主授权过的结果进入共享上下文。
- **分阶段任务。** 代码检查、文档生成或内容审批可以串起多组委派。应用回调使用相同的执行上下文与预算管理。长流程在明确的阶段边界存检查点，运行中的回调在恢复时按声明的阶段状态重建。
- **转交。** 宿主通过 `Conversation::TransferAsync` 提交目标 Agent、预期绑定版本和可选交接摘要。执行器在会话空闲且获授权时，一次提交新绑定和带 `AgentTransferred` 块的系统消息。界面可在历史中查阅交接。后续 Run 按新 Agent 计算权限，历史 Run 保留其实际执行的 Agent。

子任务的工具权限取父级授予范围、子 Agent 声明和应用策略的交集。运行时限制委派深度、并行数和全树预算。父 Run 取消时向下取消全部子任务。子任务失败按其独立结果上报，兄弟任务继续或停止由父任务的明确决策决定。并发等待用户输入时，各请求保持独立并标明发起角色，用户可以从统一待办区逐个处理。

## 会话分叉与跨会话协作

用户和获授权的 Agent 都可以创建、分叉、查找会话，引用历史与产物，并向已有会话发消息、等待或回复。会话管理和消息均在本地 `AgentRuntime` 下执行。

| 关系 | 创建和继续 | 生命周期 |
| --- | --- | --- |
| 独立会话 | 指定 Agent 定义、项目、工作区及允许带入的上下文，创建新的 `SessionId`。可同时提交一条支持回复的初始工作请求。工作请求由接收策略决定何时启动。 | 用户可以从会话列表打开、继续或取消当前 Run。发起 Run 结束后，该会话仍可接收消息和工作请求。 |
| 历史分叉 | 从源会话指定的已提交历史位置取得历史前缀，记录源 `SessionId` 和分叉点。可选择已结束的 Run 或已完成的消息，流式输出期间可以选择之前的已完成位置。 | 新会话有独立的历史后缀、Run 和交互。仅继承获准访问的历史与版本化引用，活动任务、收件箱、目标、待审批交互和一次性批准继续归原会话。 |
| 临时旁聊 | 从源会话选择消息片段和产物引用，创建临时会话用于追问或探索。结论可通过显式提交带回主会话。 | 由宿主选择是否显示在导航中。同一 Runtime 内可重新打开，持久保存的结论需取得相应的保存和共享授权。 |
| 子 Run | 由父 Run 通过 `DelegateAsync` 委派，使用同一会话中的父子关系。 | 受父 Run 的取消、权限和预算约束。 |

打开会话后可通过 `SessionSnapshot::origin` 读取获准的 `SessionOrigin`，包括创建者、发起 Run、来源会话或分叉边界。各字段按当前权限过滤，目录只展示会话摘要。分叉的历史内容可结构共享，引用使用来源会话、消息 ID 和版本定位。源会话后续写入、压缩或关闭时，已有分叉继续引用取得时的历史版本。新会话按自己的上下文和权限组装模型输入。删除或权限撤销按宿主保留规则处理，必要时用不可用占位保留来源定位。工作区选择独立于历史继承，宿主可复用当前工作区、建立 Git worktree 或复制 PPT 草稿。Agent 创建工作区的范围由宿主授权。后续应用分叉产物时使用目标的当前基线和审批。

### 协作接口

宿主通过 `AgentRuntime::Sessions()` 发现、读取历史、创建和分叉会话。受当前 Run 授权的编排通过 `RunContext::Sessions()` 调用相同服务。会话间消息走 `AgentRuntime::Collaboration()` 或 `RunContext::Collaboration()`。模型调用的内置工具沿用同一权限、审批和提交规则。 [会话服务](api-design.md#会话创建列表和历史) · [跨会话协作接口](api-design.md#跨会话协作与子-run)

- `ForkSessionRequest` 指定来源边界、会话设置和工作区选择。宿主按原命令幂等准备工作区。提交结果不明时，按原命令核对会话和目录归属后再处理。 [复制会话与 worktree](api-design.md#复制会话与-worktree)
- `SessionFilter` 和 `HistoryQuery` 供授权范围内的列表和历史分页使用。界面的名称与 `@` 选择解析为 `SessionId`，历史和产物引用携带来源标识及版本。
- `SessionMessageRequest` 指定目标会话，携带通知、工作请求或对指定 Run 的补充指令。工作请求可约定回复格式、产物类型和期限。来源主体由执行器登记。发送、回复和手动启动可返回待审批状态或消息回执。
- `ReadMessageAsync` 查询已登记的投递与回复结果。`WaitForReplyAsync` 在同一提交中读取结果或登记等待，通过请求记录向原 Run 交付结果。投递有效期、回复期限和本次等待的期限分别计算。

### 投递、等待和回复

| 情形 | 执行器行为 |
| --- | --- |
| 提交消息 | 校验发送授权和目标，记录消息及接收状态后返回回执。来源操作需要批准时由发起侧处理，接收策略可允许、暂缓或拒绝。暂缓消息由目标侧具备权限的用户确认。交互归属于会话，可在无活动 Run 时通过 `SubmitAsync` 处理。 |
| 投递通知 | 在接收方收件箱显示来源、正文及允许访问的引用。通知本身无需新建 Run。 |
| 投递工作请求 | 目标忙时进入该会话的输入队列。目标空闲且策略允许时，分配一个新根 Run；否则等待用户启动。队列中显示触发者和来源。用户通过 `StartRequestAsync` 启动已排队请求。显式用户输入优先，自动调度遵守项目配额。消费与根 Run 创建在一次提交中完成。 |
| 补充活动 Run | 需要明确的调整权限且目标 Run 与请求一致。执行器在安全边界应用补充，并按影响重新准备待执行计划。受理前目标已结束返回 `AlreadyClosed`；受理后、应用前失效时，原投递结清为 `Rejected` 并保留原因。 |
| 收到最终回复 | 核对接收会话和原请求，登记一次最终回复。已在等待的 Run 从原 `RunId` 继续，回复通过请求记录直接送达等待方。回复待接收确认时保留请求的等待状态。确认通过后结束等待，拒绝或到期时以对应原因结清。 |
| 拒收、过期或撤回 | 投递前被拒绝、到期，或由有权的发送方撤回时，记录投递终态并结清工作请求。工作请求已开始时，可以用具备目标权限的独立取消命令停止对应 Run。 |
| 等待超时或取消 | 结束本次等待并释放资源。目标任务继续按自身生命周期执行。迟到回复可供查看，已结束的等待和 Run 保持各自终态。 |
| 目标 Run 结束或工作请求达到回复期限 | 回复期限到期时，将尚未接受的最终回复按超期结清。目标 Run 在期限内结束时，保留已提交回复并等待其接收确认。尚未提交回复时，失败、取消或正常结束但缺少回复分别记录原因。目标任务按自身生命周期收尾，超期后的消息可作为关联通知保留。 |

消息可以直接交付，也可先进入 `AwaitingApproval` 或 `Queued`。批准后进入队列或完成交付。待确认或排队时可以进入 `Rejected`、`Expired` 或 `Withdrawn`。队列按会话接受顺序保留待投递项，显式用户输入和定向回复按各自的入口处理。投递结果先于调用方读取回执也是有效顺序。`Delivered` 表示接收动作已生效。通知指进入接收方可见收件箱，工作请求指创建目标 Run，补充指令指进入指定 Run 的执行上下文。要求回复的请求独立记录为等待、已回复、失败或取消，并附具体原因。不要求回复的消息以投递终态结清。同一去重键重发相同请求时取回原回执，内容不同返回冲突。目标按消息 ID 只消费一次。读取回执、已提交结果和关联会话时仍检查当前访问权限。触发的 Run 记录消息来源，UI 可以从两端跳转。

等待回复沿用当前 Run，等待前完成当前执行步骤并释放写锁和执行名额。会话仍保留该根 Run 的位置。执行器将会话占用、排队请求和项目任务依赖纳入循环检查。新增等待成环时拒绝登记，已登记的等待环则解除其中最近登记的一条，并按等待类型返回明确原因。项目或宿主按会话和因果链限制消息、唤醒、创建数量和累计预算。调度由已提交的请求和显式事件触发，读取、重放和订阅只更新投影。 [协作投递与等待契约](api-design.md#跨会话协作与子-run)

### 协作权限

- **主体与范围。** 执行器从宿主登录身份或当前 Run 的绑定上下文取得主体。宿主分别配置查找、读取、创建、分叉、引用、发送、启动和调整目标 Run 的权限，范围可限定到项目、会话、Agent 定义和工作区。相同策略用于模型工具与宿主入口。调用方只看到有权发现的目标和状态。
- **两端核对。** 发送时检查来源方和发送内容，接收前核对接收方和最新权限。接收策略可允许、暂缓供用户确认或拒绝。批准确认绑定消息版本、来源、目标及允许的动作。目标或消息变化时重新确认。
- **来源和授权传递。** 接收方将消息显示为来自具体会话的 Agent 或用户。通过请求触发的操作取接收方权限、Agent 定义、项目策略和该请求授权范围的交集。已拒绝的操作交回用户处理，只有新的用户授权能改变决定。一次性文件或工具批准由原调用持有。接收方对实际读写、导出和外部提交使用自己的授权检查与审批。
- **引用和资料。** 正文与获准共享的引用分别校验。收件箱展示、产物解析及发给模型时再核对各自的权限。会话、资源或版本失去访问权限时返回不可用状态，宿主可按权限隐藏来源详情。项目间发送需由宿主明确允许双方与具体内容的共享。

产品参考包括从指定历史位置分叉，以及接收方暂缓或拒绝跨会话消息。 [Codex App Server](https://learn.chatgpt.com/docs/app-server) · [Claude Code 跨会话消息](https://code.claude.com/docs/en/cross-session-messaging)

## 持续目标、任务依赖与项目共享上下文

### 持续目标

`Goal` 归属于一个会话，可以关联多个先后执行的根 Run 和同项目的任务。它记录由用户确认、可按版本追溯的目标与完成条件，以及累计用量和预算、当前阻塞原因和证据引用。一个会话同一时间只有一个已启用且未结束的目标。提案先处于 `Proposed`，启用后参与调度。已终结目标留在历史中。Agent 可以提出目标、拆分任务和提交完成证据。用户或宿主授权的调用负责启用、暂停、恢复和取消。预算的提高由用户或宿主决策。

| 条件 | 目标状态及调度 |
| --- | --- |
| 用户确认目标和预算 | 进入 `Active`。存在就绪工作、会话空闲、用户输入已处理且项目并发及预算允许时，可启动一个关联 Run。 |
| 缺少权限、依赖或进展 | 记录原因并进入 `Blocked`。等相关条件变化或用户指示后重新评估。 |
| 用户暂停或预算耗尽 | 分别进入 `Paused` 或 `BudgetLimited`，停止续轮。暂停后的活动 Run 可在既有预算内收尾。达到目标硬限额时按预算耗尽规则结束相关 Run；已发出的工具仍按实际结果收尾。 |
| 提交证据且依赖就绪 | 进入 `Verifying`，宿主验证器检查固定版本的证据及依赖。验证通过后按配置直接完成或进入 `AwaitingCompletionApproval`，等待会话内的完成审批。 |
| 完成审批收到决定或失效 | 批准后复核目标修订、实际证据版本与权限，通过后进入 `Completed`。拒绝、过期或证据失效时记录原因并阻止完成。 |
| 用户恢复或调整预算 | 核对当前权限和预算，更新目标状态修订后重新评估。已终结目标可作为创建新目标的来源。 |
| 用户取消 | 进入 `Cancelled`，停止目标调度并保留证据和历史。用户可通过各会话入口停止相关 Run。 |

当前 Run 的终态与目标状态分别记录。单个 Run 成功可作为进展证据，目标以整体完成条件判定。用户输入优先于自动续轮。调度以本次目标版本和尝试 ID 登记。跨会话派生工作的用量可归入发起侧目标，由宿主在接受请求时确认归属和额度。在调度前预留，完成后按实结算。目标暂停、预算耗尽或阻塞时，界面显示原因和下一步可用操作。目标可以在同一设备持久化，自动继续取决于宿主应用运行和恢复策略。

宿主按目标设定 `GoalCompletionPolicy` 并可在完成阶段要求确认。需确认时，执行器用 `OperationApproval` 绑定提交证据的命令、目标修订、依赖和证据版本。验证和待审核期间暂停目标自动续轮。暂停、取消、改动目标或提交新证据时，旧验证或审核失效。重启后可在重新检查绑定和权限后恢复同一审核。 [目标完成验证与人审](api-design.md#目标完成验证与人审)

### 执行中修改目标

用户可在 Goal 面板预览并修改目标说明、完成条件或完成策略。Agent 可提出修改，用户确认后生效。目标沿用原 `GoalId`，生成新的目标定义版本。历史 Run、任务尝试、产物和累计用量均可追溯。预算和任务关联通过各自命令调整。

修改提交时，主会话里按旧目标执行的 Run 停止接受新工作，尚未发出的计划及审批失效，已开始的工具按实际效果收尾。绑定旧目标且已经开始的独立会话按原任务继续，用户可单独停止。独立任务的审批仍由执行会话处理。还未启动的旧派发需重新安排。旧完成审批结清，已有证据可引用到新版本重新验证。主会话空闲后，新的 Run 按新版本和当前授权推进。 [执行中修改目标 API](api-design.md#执行中修改目标)

### 可分配的任务与依赖

项目任务的身份、负责人和状态独立于会话和 Run。任务可由用户、Agent 或业务事件提出，包含项目 ID、执行说明、负责人、输入引用和完成条件，结束后记录证据和产物。负责人可以是会话或由宿主选择的 Agent 定义。领取任务时以任务版本进行条件更新，记录唯一有效的领取者，实际执行的 Run 与该次领取关联。

任务依赖使用同一项目内的有向无环图。边引用前置任务及其需要交付的结果，新增和修改时使用项目修订进行并发检查，并验证无环。默认在上游任务成功且必需产物可用后进入就绪状态。上游失败、取消或产物失效时，下游显示阻塞原因。宿主可显式配置接受部分结果的规则。重试上游时保留历史执行，下游按规则重新计算就绪状态。发布结果后若上游更新，已使用该版本的下游结果保留原引用，并标记可用的新版本；是否重跑由宿主或用户决定。

任务从 `Pending` 根据依赖进入 `Blocked` 或 `Ready`，领取后为 `Assigned`，绑定执行时进入 `Running`。Run 成功后可继续等证据提交或验证。验证通过且交付结果后任务进入 `Succeeded`，失败或取消分别进入 `Failed`、`Cancelled`。已结束任务可由显式重试创建新的尝试。解除未开始的领取后重新计算就绪状态。一个会话按根 Run 并发规则调度任务，多会话可并行领取不同任务。发布状态变化、原因、关联的目标、会话、Run 和产物，供任务看板和审批待办使用。

### 项目共享上下文

项目由宿主提供稳定 `ProjectId`，绑定工作区、成员范围和访问策略。共享项可以是要求、决策、术语、资料、摘要或版本化产物引用。每项有稳定 ID，记录来源、发布者、版本和允许的访问范围。Agent 在获准的范围内提出或发布共享项，宿主可以要求审核后生效。加入项目的聊天片段需要作者或宿主明确选择，并保留来源标识。共享项可从草稿经审核发布，撤回后按权限保留版本记录。发布和撤回使用版本检查，既有 Run 保留用于追溯的引用。

发布替换版本时记录此前最近的已发布版本，撤回已发布版本时记录该版本的撤回。变更和对应的发布或撤回在同一事务提交，获准的调用方用原命令查询影响。撤回后可在当前权限范围内查看来源标识及受影响的产物，正文仍不可读取。

现有 `ContextProvider` 可按项目和指定版本读取共享项，按当前 Agent、Run 和模型接收方授权及上下文预算选取内容。Run 记录实际使用的版本。关键信息过期、撤销或替换时，在下次读取和发送模型前重新校验。宿主可视情况提示来源变更或为待执行的操作重新生成预览。聊天上下文压缩只改变模型装配，保留会话历史和引用定位。摘要记录覆盖的来源范围，按预算选用。项目指令由宿主明确授予并和普通共享资料分别处理，后者作为模型输入的数据。

### 目标与项目接口

| 调用入口 | 职责 |
| --- | --- |
| `Conversation::Goals()` 与 `RunContext::Goals()` | 通过 `ReadAsync`、`ObserveAsync` 读取和关注当前目标，以 `PreviewEditAsync` 检查修改影响，再用 `UpdateAsync` 提交目标命令。Agent 可用的命令由定义和策略声明。 |
| `AgentRuntime::Projects()` 与 `RunContext::Projects()` | 读取和订阅项目快照，通过 `UpdateTaskAsync` 管理任务，`UpdateContextAsync` 管理共享项，`ReadContextAsync` 读取指定版本。 |
| `GoalVerifier` 与 `ContextProvider` | 提供完成条件验证和获授权的资料。验证器返回通过、缺少证据或失败。执行器提交完成前复核版本及证据，按目标策略发起人工确认。 |

写操作携带命令 ID 与适用的预期修订。创建任务和改动依赖使用项目预期修订。回执关联对象、修订及提交事件，执行结果由状态更新提供。`WaitForTaskAsync` 通过 `TaskExecutionRef` 绑定明确的执行尝试。Run 内等待复用等待关系检查和本地恢复。 [目标与项目 API](api-design.md#项目任务持续目标和共享上下文) · [Codex Goals](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex) · [Cursor Projects](https://cursor.com/docs/agent/projects)

## 文件、产物和宿主授权

`ArtifactRef` 由稳定产物 ID 和不可变版本组成。名称、类型和可用的大小由 `ArtifactMetadata` 提供。审批使用明确的产物版本。补丁、诊断列表、设计稿、截图、结构化大纲和 PPTX 文件都可作为产物引用挂到会话、Run 或项目任务。宿主的产物服务按当前用户解析 `ArtifactRef`，返回可用的预览、读取和打开能力，默认卡片按能力呈现。渲染器以产物类型注册，接收对应版本的预览数据和受限的动作入口。保存和覆盖动作调用相应的宿主工具，进入同一审批流程。

文件读取和保存通过宿主提供的资源授权完成。本地工具可以接收 HuxerUI 的 `FileReference`，持久化会话保存由宿主重新解析的产物版本引用。业务渲染器可提供逐文件差异、幻灯片缩略图和正文摘要。普通附件可用有上限的缓冲读取，较大的文件通过宿主提供的 `AsyncInputStream` 读取。 [文件与选择器](https://github.com/HuxerUI/HuxerUI/blob/main/include/huxerui/file.h)

### 审批与写入规则

- **内容确认和操作授权。** 用户提交受众、修订或确认大纲时，执行器记录用户选定的内容，宿主按这一版继续。对工作区写入、用户选定位置的保存或外部提交，需要确认时展示具体目标、操作内容和影响，例如逐文件差异或被导出的文件版本。Preview 的默认 `Ask` 策略要求人工确认代码应用和正式文件导出。生成应用内暂存产物可由宿主按已授予的范围允许。文件选择器由宿主响应用户动作打开，并将用户授权的目标转换为执行器可引用的资源。
- **批准绑定一个调用。** 执行器登记提交者、会话、Run、交互版本、调用 ID、工具 ID 及版本、已验证参数、目标资源和基线版本，以及预览或产物版本。客户端只提交对当前交互的决定。执行时取出已批准的不可变计划和同一版本的输入，批准只绑定一个逻辑调用。恢复时沿用原调用 ID，仅在确认尚未发出或满足工具声明的幂等条件且授权仍有效时才可调度。内容、参数或目标变化时需要重新准备计划并审批。
- **可选自动审查。** 宿主可用规则或独立的小模型审查获准的工具计划。审查器收到经授权的版本化预览和范围，给出批准、拒绝或转人工。自动批准绑定原计划并记录审查器与理由，执行前重新核对权限及版本。配置要求人工确认时直接发给用户。审查器超时或无法作决定时也转人工。 [宿主自定义工具审批](api-design.md#宿主自定义工具审批)
- **以实际写入时的状态为准。** 提交时验证交互、版本、身份和当前授权。调用前再次核对授权、版本和计划，宿主在实际写入的临界区复核资源版本或使用条件写入。创建新文件时，预期目标不存在也属于版本约束。目标变化时将旧调用登记为冲突，重新准备预览并创建审批后才能执行新调用。撤销授权则关闭该调用。涉及同一资源的并发写入由宿主按目标协调。
- **记录实际副作用。** 多文件写入若部分完成，宿主逐项报告已应用、未应用及待核对事项。测试失败、PPTX 生成失败和导出失败分别记录所处阶段及产物状态。取消或断线后结果未知的写入需经宿主核对。用户可在界面看到失败前已经完成的修改和产物。
- **授权和模型输入。** 模型文本、网页、工具输出、跨会话消息和 Skill 配套资料按外部数据处理。获准激活的 Skill 正文按当前 Run 的流程指令装配。显示和模型上下文分别按宿主策略过滤，外部链接和界面动作走宿主登记的入口。凭据由宿主或其授权服务管理，审计记录授权决定、实际工具、用时和结果摘要，按宿主的策略脱敏和保留。

## 回撤、分叉审阅与产物返工

三个能力复用版本化产物、宿主准备的变更计划、操作确认和实际执行记录。AgentKit 管理这些对象与会话、Run、项目任务的关系。宿主提供业务资源的版本解析、差异、恢复和局部生成。

### 回撤已执行的变更

Run 停止后，执行器保留原调用及其已发生的副作用。支持回撤的写入工具在准备阶段声明可恢复范围和所需记录，由宿主在写入前保存变更前的版本或生成反向变更所需的数据。执行结果按资源登记实际影响、写入后的版本，以及宿主恢复数据的受控引用。只保存了历史引用的资源可显示变更依据。界面根据实际执行结果和仍可读取的恢复资料显示可回撤、部分可回撤、需核对或不可回撤。

用户从执行记录选择回撤目标。执行器以新的命令和工具调用请宿主准备反向补丁、文档版本恢复或其他补偿计划，展示原调用、实际影响、目标及恢复范围。审批绑定反向计划与当前目标版本。审批后由宿主在写入边界重新校验权限和版本。原写入之后出现其他变化时报告冲突，可由宿主生成保留用户后续修改的新计划以供审阅。外部发布和发送的回撤取决于宿主能否确认并提供补偿能力。结果未知的资源先核对实际状态，确认可逆的部分再进入计划。

回撤结果区分完成、部分完成、失败和待核对，并逐资源记录实际结果。原 Run 状态、审批和工具结果保留。回撤成功会产生资源的新版本，并触发依赖影响检查。同一回撤命令重发可取回原回执。对已回撤的资源再次请求时，执行器以原调用、作用范围和资源的当前版本核对，返回已有结果或要求准备新计划。

Preview 从代码助手的「已应用变更」审阅页进入回撤。用户选择要恢复的文件后，回到对话审阅反向差异并批准。宿主在首次写入前把原始内容和已审阅的新内容保存到应用恢复目录，写入结果仅登记受控引用。审批等待期间若有任一选中文件被编辑，宿主报告版本冲突并保留用户内容。

设计助手从带有恢复记录的当前设计版本准备回撤。审批可打开当前画板和将恢复的前一版画板。批准后按当前版本条件发布新版本，按字节保留历史设计，并登记所复制的旧版及本次被替换的版本。准备完成后若排队期间已发布一份较新的设计，原回撤计划报版本冲突。重启后可以继续审阅同一计划和两个原版本。

### 分叉方案审阅与应用

用户或获授权的 Agent 从同一已提交历史位置发起方案比较。记录共同的任务要求、输入版本和比较条件，为每个分支创建独立会话。宿主可以分配代码 worktree、设计文档副本或 PPT 草稿副本。涉及写入的分支在宿主分配的隔离范围内准备方案。使用共享工作区时，候选以预览或暂存产物提交。不同方案可在共享预算内并行执行，分别记录模型与验证条件、失败、进度、时耗和用量。

持久模式将比较、各分支会话和首个 Run 一起提交，确认提交后才启动分支。共享工作区的候选可以读取和生成暂存产物。运行时在工具准备前拦截工作区写入和外部提交。分支需要执行这些操作时，由宿主准备独立工作区，并按该工作区复核实际操作授权。

各分支沿用项目任务的执行状态，成功时返回带版本的候选、验证结果和来源，失败时保留相应诊断。审阅视图按已授权的字段并排展示差异、关键证据和成本，能跳回各分支并查看其验证环境。宿主提供代码、设计节点或幻灯片的差异与可合入能力。用户选定候选后，业务工具以选中版本对当前目标准备应用计划，生成新预览并按实际目标审批。分支内的批准归原调用。应用到主工作区或主文档使用新的调用和批准。目标基线有变化时报告冲突，并由宿主按新基线生成可审阅计划。没有合入能力的产物可引用或另存。

Preview 在源会话工具栏打开「比较方案」。一次提交固定共同的已提交历史、可读产物版本和比较要求，为两个思路创建分支。比较在原工作区主区域显示，宽窗口并排、窄窗口纵向排列。切到分支处理表单后，可用「返回比较」回到同一组候选。比较页可按节点 ID 查看画板差异，或同步翻看两份候选演示的同页内容，并查看各分支的状态、模型和用量。重启后从源会话重新打开同一比较。

宿主要求批准比较或其中的候选会话时，Preview 回到源会话展示同一条待办，用户能查看比较要求、候选任务和版本引用。批准前保留原命令和检查结果，工作区分配及分支执行等待批准。重启后可处理同一审批。审批通过并提交后，从源会话的比较列表打开本次比较。拒绝或批准后发现授权变化时，在原命令中保留处理结果。

Preview 的代码比较先显示两份候选共同的 Git 提交、各自分支和本地路径。确认后才创建独立 worktree。分支中审批和测试绑定各自工作区。比较页从候选的已记录文件版本展示逐文件差异及测试结果。合入前复核主工作区与候选补丁的前置内容，准备主工作区的逐文件审批。审批后发现内容变化时保留用户编辑，差异须重备。成功合入会保留每个文件的候选来源和恢复记录。

代码比较先保存命令和候选计划，再分配 worktree。应用重启时复用原命令和已经核对归属的 checkout，提交结果确定后才启动分支。明确失败的比较可从会话目录核对未使用的候选 checkout，显示失败原因、提交、分支和路径。用户确认后，宿主先封存副本计划，再检查并移除干净的 checkout 和工作区登记，保留 Git 分支。结果仍不明确、目录被占用或包含用户文件时，保留现场供核对。

采纳中断后从比较页核对原调用的结果。代码按批准范围逐文件查阅已登记的替换记录和恢复版本，设计稿和 PPT 核对原调用是否登记了新版。结果可确认为应用、未应用或部分应用，证据不足时保留待核对状态。核对只登记已发生的效果并保留用户后续修改。确认部分应用后，可根据已知效果准备回撤，或按当前基线准备新的差异和审批。

Preview 的设计稿和 PowerPoint 采纳以源会话内同类产物的当前版本为目标。审批可打开目标版本和选中的候选。批准后，画板发布为同一设计的新版本并登记可回撤的变更。PowerPoint 将候选的完整 PPTX 发布为同一演示的新版本，并记录逐页来源。原版本和候选仍可打开，导出新版需要对确切保存路径另行批准。对于只支持整份替换的适配器，选中局部节点或页面时返回扩大范围的建议，由用户另行决定是否采纳整份产物。

### 按产物来源定位与执行返工

产物引用包含稳定的产物 ID 和版本。宿主可为产物声明稳定片段 ID，例如设计稿的节点、补丁覆盖的文件或区域、测试报告的条目、PPT 的页面和元素。工具交付产物时登记输入的版本和实际使用的片段，以及哪些输出片段依赖这些输入。来源边指向已提交的资源、共享项或产物版本。更新同一产物时，用旧版本登记输入。无法可靠定位时登记到整个产物或更粗的范围。渲染器可从产物或片段跳到授权可见的来源。运行时以已登记的依赖为依据，模型建议可供宿主核对后登记。

当来源产物、项目共享项或资源版本更新、撤回或回撤时，执行器沿已登记依赖计算直接和传递影响。宿主可以提供精确的变更片段和映射。界面分别展示原版本、建议替换的版本、受影响片段和须复核的预览。准备中的操作若固定使用的来源失效，在下一次调度前重新解析并按情况更新预览和审批。历史结果与已发布文件保留各自的来源版本。新的执行按当前权限解析引用，影响记录供后续返工。被撤回的来源按权限显示不可用。依赖不明时把上游影响标到整个产物。

项目中的产物升版和来源变更记录一同提交。局部返工记录批准的片段，缺少片段信息时记录整份。与计划输入重叠的变更提交后，未发出的调用结束为冲突，原待批交互失效。用户可核对新来源再准备和审批。已发出的写入保留原调用及核对记录。

用户或获授权的 Agent 选择受影响片段，用当前基线和指定的新来源版本生成返工计划。宿主提供局部重生成与比较，执行器登记新的产物版本及依赖。原版本继续可查。由宿主校验未选中片段的内容和稳定 ID，并持久化本次替换的范围。目标写入或再次导出按新计划走审批。宿主只支持整份重生成时，先返回 `ScopeExpansionRequired` 及建议范围，用户明确接受后以新命令提交。返工由提交的范围触发调度，其他关联任务收到状态提示。

Preview 在验证报告的原位概要中提供「查找受影响的幻灯片」。结果显示当前项目可见的演示版本与页面。点击一项，复核授权和版本后打开演示所属会话的对应页。若所列页面已失效，保留报告概要并提示更新结果。用户可在审阅页选择新报告，经原会话审批后生成新版。

### 接入与恢复

`AgentRuntime::Artifacts()` 与受当前 Run 授权的 `RunContext::Artifacts()` 提供产物读取、预览、流式打开、影响查询、来源变更记录和返工或回撤准备。`ReworkRequest` 指定目标会话、产物基线、替换来源、片段及受影响的写入目标。`RevertRequest` 绑定原调用及目标的预期当前版本。宿主通过 `ChangeAdapters` 提供实际比较、恢复和局部生成。 [产物与变更 API](api-design.md#产物分叉审阅返工和回撤)

`AgentRuntime::ForkReviews()` 与 `RunContext::ForkReviews()` 创建、读取、订阅和关闭分叉比较。采纳方案通过 `PrepareAdoptionAsync` 绑定比较修订、候选版本及当前目标基线。关闭比较时保留候选，分支 Run 由各会话管理。 [分叉审阅和合入](api-design.md#分叉审阅和合入)

准备命令可在有权限的当前 Run 内受理，也可在目标会话排队。回执关联已登记的队列项、调用或审批。实际写入使用工具的准备、审批与调度流程。查询按会话、项目和产物权限过滤。

持久化记录原调用、资源影响、可回撤范围、比较基线、候选与选定版本、输入和输出依赖及未完成的准备计划。产物版本和依赖关系在同一次提交中可见。反向索引可从已提交关系重建，影响查询核对索引对应的项目修订。批准及回撤、返工和分叉应用采用现有命令去重与版本检查。子会话创建与比较记录提交后再启动分支，重启时用登记的分支 ID 和执行尝试恢复。恢复写入时核对授权、资源版本及已知副作用。索引查询、打开预览和检查影响只更新界面状态。宿主负责实际备份与恢复数据的保留，根据权限回收载荷并保留允许查看的操作记录。

## 构建与平台交付

库以 `Lib-AgentKit` 独立发布，公共命名空间为 `huxerui::agentkit`，入口头文件为 `<huxerui/agentkit.h>`。应用可独立链接 `HuxerUI::AgentKitRuntime`，需要默认 UI 时链接 `HuxerUI::AgentKit`。会话与执行、UI、协议适配器分开组织公开头文件。提供商与外部协议适配器按需启用，库内复用一个私有 JSON 编解码实现。默认 UI 使用本地会话，模型可由宿主配置为本地或云端提供商。库通过公开 SDK 构建，带 composable 标记的实现交给现有 codegen。

```cmake
huxerui_use_library(my_app
    TARGET HuxerUI::AgentKit
    PATH "libraries/Lib-AgentKit"
)
```

库内部依赖走现有的 CMake 库关系，保持 `HUXERUI_LIBRARY_GRAPH_ONLY` 下的声明可解析。普通组件、主题资源和模型调用复用公共 API。将来需要平台专属预览或宿主模块时，通过已有平台包接入。iOS 的 Swift 包遵循 `platform/ios/<Swift 产品名>/`，Android 的附加宿主模块由对应的 Gradle 库管理。对库的源码发行记录支持的 HuxerUI SDK 版本、编译方式和适配器版本。C++ API、存储 schema 和第三方扩展各按自身契约演进。存储升级有显式迁移和失败恢复策略，适配器各自公布兼容版本及能力。 [HuxerUI SDK 库约定](https://github.com/HuxerUI/HuxerUI/blob/main/docs/design/sdk-cli.md)

| 环境 | 交付能力 |
| --- | --- |
| macOS、Windows、Linux | 对话 UI 和本地 C++ 执行。项目文件、进程工具和本地模型由宿主显式注册。 |
| iOS、Android | 对话 UI 和受应用生命周期约束的本地 C++ 执行。 |
| Web | 对话 UI、浏览器内执行和浏览器允许的工具。API 密钥和通用 MCP 接入可放在应用服务端。大文件和用户手势约束按浏览器能力处理。 |

平台适配以宿主声明的能力为准。Web 上的网络适配器按需验证 CORS 和响应体流式读取。网络与渲染能力相同的地方复用同一条实现路径。 [HuxerUI Web HTTP 后端](https://github.com/HuxerUI/HuxerUI/blob/main/docs/design/http.md) · [HuxerUI 平台能力](https://github.com/HuxerUI/HuxerUI/blob/main/docs/guide/platforms.md)

## Preview 应用

沿用 `examples/preview`，交付一个 AgentKit Preview App。应用级服务持有一个 `AgentRuntime`，四个助手共用模型适配器、会话存储、审批和产物服务，可在同一个项目中协作。代码、PPT、设计和通用助手分别以 `AgentDefinition` 注册。桌面窗口左侧是一个会话列表，主区域显示对话与输入，审阅时切换为详情。窄窗口通过单一入口打开导航。

| 助手 | 宿主提供的上下文、工具与界面 |
| --- | --- |
| 代码助手 | 授权工作区、编辑器内容及文件版本，读取、生成和应用补丁、运行宿主配置的测试，显示逐文件差异和诊断。 |
| PPT 助手 | 参考资料、主题和模板，大纲编辑、PPTX 生成及保存，显示可编辑大纲和逐页预览。 |
| 设计助手 | 需求、组件目录和设计文档，生成或修订带稳定节点 ID 的结构化设计稿，显示画板和标注，返回可引用的设计稿及预览。Preview 由宿主提供设计文档与渲染工具。 |
| 通用助手 | 应用注册的跨领域工具和可联络的 Agent，展示主任务计划、等待状态、协作会话和最终产物。用户可以在同一对话里连续提交不同领域的任务。 |

### 导航、新建与工作区

侧栏与主区域使用中性色表面，强调色用于选中、焦点和主要动作。侧栏的「新建对话」为无底色、无边框的平面入口。常驻入口还有「打开文件夹」及「待处理」。会话列表混合显示各助手的会话，每项可识别标题、当前助手及运行或待处理状态。用户按 `SessionId` 直接打开对话。会话切换保留各自的草稿、运行、待办和工作区。统一待处理入口定位至所属会话的具体请求。

打开文件夹使用系统目录选择器。宿主登记可用的 `WorkspaceId`，在新建草稿中预选该目录，并显示可核对的本地路径。已有会话继续绑定原目录。目录不可访问时保留操作前的草稿并提示重新选择。文件读写、进程执行和送入模型各自按实际操作授权。

「新建归类」创建用户的会话目录，可折叠、改名、调整顺序和移除。会话可以移入归类或直接放在根列表。移除归类时将成员移回根列表。宿主按本地用户保存导航数据，用 `SessionId` 与运行时目录合并。移动归类只修改导航元数据。 [Preview 导航与工作区](api-design.md#preview-导航与工作区)

「新建对话」先打开输入草稿，默认选中通用助手。用户可在首条消息前改选代码、PPT 或设计助手，并选择工作区和归类。首条输入提交后，会话以已有标题出现在列表中。会话列表订阅 `ObserveListAsync`，包括未打开的会话。已有会话可在空闲时显式转交。 [新建、列表和转交](api-design.md#会话创建列表和历史)

标题随首条已提交的用户输入或可见协作任务文本生成。用户已指定标题时沿用该值，空会话显示宿主配置的占位标题。可选的宿主标题生成器异步优化，标题更新走会话和列表订阅，手动改名优先。改名和优化只更新元数据。 [会话标题](api-design.md#会话标题)

### 会话菜单、复制与删除

右键、行尾「…」和键盘打开同一会话菜单。用户可以重命名、移动到归类、复制和删除。删除活动会话前需要先结束任务；确认时显示记录和引用的处理范围。删除命令只处理会话及其归类关联，工作区、worktree 和已导出文件由宿主的独立操作管理。

「复制对话」从最近已提交且可见的历史边界分叉。代码会话绑定可用 Git 仓库时可以选择「复制到 worktree」。确认页展示源 commit、新分支和目标目录。宿主从该提交创建干净的 worktree，已提交会话后再打开副本。源侧未提交的改动、暂存、未跟踪文件及待应用补丁由独立的变更计划处理。

副本继承边界内获准的消息和版本引用，可预选原助手及适用模型。目标重新计算工作区授权，权限选项从 `Ask` 开始。源 Run、审批、队列、草稿、收件箱、目标和任务领取按原归属保留。分配失败时保留表单和源会话；分配成功但提交结果不确定时按原命令核对后再恢复或清理。 [复制会话与 worktree](api-design.md#复制会话与-worktree)

### 输入、模型与权限

输入栏常驻模型和权限入口。模型列表展示宿主已注册且适用于当前助手的配置。运行时分别显示「本次」和所选「下次」。当前 Run 固定启动时的模型与权限预设。改选影响之后提交的新建、空闲发送或排队。已入队项保留受理时的模型修订和预设，启动前按当前授权再校验。失效时保留输入及原因，由用户改选后重新提交。

| 权限模式 | 行为 |
| --- | --- |
| `Ask` | 默认。按宿主授权执行低风险操作，需确认的操作展示实际计划并等用户确认。 |
| `Auto Review` | 宿主可把符合条件的准备完成计划委托给审查器。无法决定、失败或超时时转人工。 |
| `Full Access` | 在组织允许时，由用户确认工作区、操作范围与有效期。宿主可豁免范围内的逐次审批。组织强制人工审批和资源限制继续生效。 |

用户界面改选用于后续任务。撤权、过期和强制人审规则收紧立即参与执行前核对。未执行的旧计划或批准重新按当前策略处理，已开始的写入按原调用核对。 [模型与权限选择](api-design.md#preview-的模型与权限选择) · [宿主审批预设](api-design.md#审批预设的宿主绑定)

空闲时只显示「发送」。活动 Run 期间才显示「直接发送 / 排队」，默认直接发送到当前 Run，沿用该 Run 已绑定的配置。补充受理后以「等待应用」「已应用」或「未生效」显示结果。受补充影响的旧写入计划结清并等待新预览。现有表单或审批继续在对应位置提交。目标 Run 结束、替换或正在取消时保留草稿，用户可以明确选择「作为新任务发送」或「排队」。 [运行中发送与补充](api-design.md#运行中发送与补充)

### 审阅、引用与旁聊

短报告、少量日志和来源摘要在消息原处展开。代码差异、幻灯片和交互设计稿进入同窗口审阅页，占满主区域。返回恢复对话滚动位置、草稿与焦点；再次打开同一版本时还原所选文件、页码或节点。多屏对照可从审阅页主动打开独立窗口。所有入口观察同一交互 ID 和版本，批准所针对的目标、预览和版本在操作附近展示。已处理或已失效的审批在原处显示状态。

PowerPoint 审阅页可从产物所属会话导出正在查看的确切版本。用户输入文件名后回到该会话核对完整保存路径并批准。新版和旧版分别按其版本受理，已有文件发生路径冲突时保留原文件。 [产物动作与审批](api-design.md#自定义对话组件与动作)

选中对话文字或产物片段后出现「旁聊」和「引用到输入框」，键盘可从内容操作触发同样入口。选区绑定消息块、文件片段、幻灯片页或元素、设计节点和来源版本。打开旁聊先保留选区和原位置，提交问题后以所选片段建立临时会话。旁聊使用自己的模型调用、只读能力和预算，关闭弹窗回到原位置。

「引用到输入框」与「带回结论」先更新主对话草稿。用户可以审核、移除引用或继续编辑。显式发送时按实际目标及模型重新检查来源，接受后把所选结论作为版本化引用内容随消息或队列提交。未提交的旁聊保留在本次 Runtime；重启时，指向失效临时回复的草稿标注不可用。选区过期或授权撤回时保留其他草稿，并让用户重新选取或移除。 [来源选区与旁聊](api-design.md#来源选区与旁聊)

通用助手使用常规 `AgentDefinition`。所属定义声明指令、上下文来源、可直接使用的工具、可联络的 Agent 和协作操作范围，宿主策略再结合项目、工作区和资源确定实际权限。同一条对话既能直接执行一个简单任务，也能在一条 Run 内调用工具、拆分项目任务、联系已有专用会话或新建会话、等待结果并汇总产物。涉及审批的操作总是通过实际执行会话的工具入口处理。需要固定业务顺序时，宿主用 `RunHandler` 定义阶段，例如设计获确认后才交给代码助手。

会话中的 Goal 面板通过 `Goals()` 读取和订阅目标，显示当前状态、预算、进展、证据和阻塞原因。用户可设置目标，确认后启用，并可修改、暂停、恢复或取消。修改前显示需要收尾的 Run、受影响的调用和继续执行的独立工作。目标状态和当前 Run 分开显示，完成待办可从统一待办进入。 [Goal 界面契约](api-design.md#goal-模式的宿主界面)

## 首版端到端验收

首版发布在同一个 Preview App 内同时验收代码助手和 PPT 助手。两条流程在具备所需文件与进程能力的桌面环境运行，共用一个真实模型适配器完成集成验收，并使用可编程的假模型和工具验证事件顺序、竞争和失败。代码侧展示嵌入工作区的交互组件，PPT 侧使用默认 `AgentChat` 并注册业务卡片。两者共用 `Conversation` 的操作、模型轮次、工具审批、Run 状态和产物引用。

### 代码助手

- 用户选择授权项目和修改范围，提交普通功能或修复任务。宿主提供当前文件和编辑器内容的版本、读取工具和引用定位。
- 模型按需读取上下文，生成多文件补丁。宿主工具以原文件版本生成差异预览，AgentKit 创建待审批交互并显示变更目标。用户批准后，宿主按已批准的补丁和基线版本应用修改。
- 补丁应用完成后，宿主编排通过同一工具入口调用注册的测试工具，输出退出状态、诊断和涉及文件。验收检查工作区的实际修改与批准预览一致，测试结果和代码修改的结果分别可见。
- 专项用例覆盖审批等待时文件或编辑器缓冲区变化、补丁应用部分失败和测试失败。资源版本变化时旧补丁不会写入，需要根据新基线重新生成预览和审批。

### PPT 助手

- 用户输入主题并选用参考资料。宿主提供资料内容和模板，AgentKit 通过表单收集受众、风格和篇幅要求，流式展示主题和大纲。
- 宿主编排将结构化大纲交给可编辑卡片，用户修改并提交后，生成器只使用已确认版本。宿主生成实际 PPTX 暂存产物和预览，AgentKit 发布进度、产物引用与可用动作。
- 同一 Run 等待用户选择保存位置，操作确认绑定 PPTX 版本和目标。宿主完成导出并报告结果。验收打开导出的 PPTX，并核对页结构和关键文字是否反映最后确认的大纲。
- 专项用例覆盖大纲修订、PPTX 生成失败和文件导出失败。生成后直接用工具结果返回的 PPTX 版本准备导出，重启后核对同一版本。导出失败时，已生成的暂存产物仍可预览，由宿主报告失败原因。

### 共用验收用例

| 情形 | 预期结果 |
| --- | --- |
| 代码或 PPT 会话等待输入或审批时，从同一列表打开另一条会话，再切回或从另一个窗口进入 | 列表显示各自的标题、助手和待处理状态，点击后直接打开目标对话。切回后仍能看到原 Run、待处理请求和已生成的内容，提交后继续原 `RunId`。 |
| 表单错误、命令重发、双窗口同时提交 | 字段错误保留草稿和待处理请求。同一命令重发返回原回执。竞争提交只有一次被接受且最多执行一次获批的调用。 |
| 首条发送时生成标题，随后手动改名 | 会话首次出现时已有标题。空会话首次发送时同步更名，用户的手动标题优先于晚到的自动结果。标题变更不会重排目录。 |
| Run 活动时补充已准备的代码或 PPT 任务 | 消息绑定当前 Run。尚未开始且受影响的写入计划结清，已开始的写入按原调用核对。显式排队只在当前 Run 后消费。 |
| 发送补充时原 Run 刚结束，或补充尚未应用就结束 | 草稿或未应用消息可找回。用户明确选择后才能另发或排队。两个窗口或重启后保持相同归属与顺序。 |
| 运行时从模型和权限配置 A 改选 B，用 B 排队后再改选 C | 直接发送仍进入 A 的 Run，队列固定 B，空闲新发使用 C。B 的模型版本、能力或授权失效时按原因结清队列项，输入可找回。 |
| 审批拒绝、交互过期、目标变化或授权撤销 | 执行器展示对应状态。待审批操作保持未执行。资源变化后应提交新的预览和审批。 |
| 等待中取消、执行中取消、晚到的工具结果 | 关闭待处理交互，停止新模型轮次和工具调度，Run 只有一个终态。已发生及无法确认的写入分别可见。 |
| 模型流中断、工具参数分片、预算耗尽 | 中断时保留已经显示的内容，丢弃该轮待调度的调用。正常完成的轮次按顺序调度完整调用，超限返回明确原因。重放同一事件序列得到相同投影。 |

首版还验证 SDK 消费者构建、长对话和流式滚动锚点、中文 IME 与输入焦点、虚拟项重新挂载，以及回执与事件以不同顺序到达。两个示例的必要步骤失败，或必需审批被拒绝或过期时，以相应原因结束 Run，并展示已经产生的修改或产物。事件和工具日志记录开始、首次可见内容、等待、工具耗时、结束和用量。首版重启验收覆盖这两条流程的检查点、未完成审批、补充及队列、已登记产物和未知写入核对。完整版扩展到协作等待和项目状态恢复，再按目标平台补充设备及性能用例。 [API 验收和故障注入](api-design.md#端到端用例)

## 完整版端到端验收

### 会话切换、新建与通用助手

点击「新建对话」，沿用默认通用助手提交首条消息，确认新会话显示为通用助手。分别新建并在发送前选中代码、PPT 和设计助手，核对各自选择的 `AgentDefinition` 和工具范围。四类会话都出现在同一列表。

代码会话等待补丁审批时，从列表直接打开设计会话查看设计稿，再打开 PPT 会话编辑大纲。切回代码会话后仍可核对原预览并处理同一审批。核对各会话的历史、草稿、当前 Run、待办和工作区归属。打开统一待办中的请求时，跳到请求所属的会话。

在同一个通用助手对话里先提交一个可直接完成的请求，例如用现有报告生成一页发布大纲。确认通用 Agent 直接调用已注册的报告读取和大纲工具，并在该对话交付大纲。再提交需要跨领域的完整任务，主对话继续用于澄清、看进度和接收产物。验收时核对运行记录中的两种路径、实际执行的 Agent 和授权范围。

### Preview 工作区、审阅与旁聊

| 情形 | 预期结果 |
| --- | --- |
| 打开目录并新建，移入归类后再移回根列表 | 工作区和会话归属一致，选中态与草稿可恢复。右键、行尾入口和键盘可完成同样操作。删除会话确认后，工作区和导出文件可继续访问。 |
| 源代码会话待审批，复制到 worktree | 新会话使用已确认 commit、目标路径和新分支，只继承获准的历史和引用。新会话从 `Ask` 开始，原计划仍在源会话。路径或分支冲突、撤权及提交结果不明时按原命令核对。 |
| 在同窗口进入审阅页，再返回对话，随后从独立窗口处理同一请求 | 还原滚动、焦点、草稿和审阅位置。任一窗口批准后，另一入口更新原交互状态。过时的按钮无法批准新版计划。 |
| 从中文消息、差异行或 PPT 第 3 页选区发起旁聊 | 可查看精确片段与来源版本。关闭弹窗回到原处；带回结论先进入草稿。显式提交或排队受理后结论可恢复，选区失效或撤权时保留其他草稿并提示处理。 |

### 设计 → 实现 → 验证 → 做 PPT

用户在通用助手对话提出「设计一个设置页面，实现并验证，再做发布演示」。通用助手提议持续目标，用户确认目标和预算后，由获授权的通用助手建立项目任务依赖并选择专用 Agent。项目中预先打开一条 PPT 会话，用来验收向已有会话发起工作请求。

| 阶段 | 场景和验收结果 |
| --- | --- |
| 设计 | 通用助手请设计 Agent 在独立会话生成结构化设计稿。用户查看画板并确认，得到可定位节点的设计版本。设计 Agent 通过原请求回复设计稿和预览。 |
| 实现 | 代码 Agent 获准读取选定的设计版本，生成补丁及差异。用户批准对应基线和范围后应用修改。记录设计节点与实现文件的来源关系。 |
| 验证 | 代码 Agent 创建独立验证会话，提交实现版本、授权的测试范围与预期结果。验证 Agent 运行宿主配置的测试并采集实现截图，回复带版本的报告和截图。测试未通过时，发布任务显示阻塞。 |
| 做 PPT | 通用助手向已有 PPT 会话发送工作请求，附指定版本的设计稿、测试报告和截图。PPT Agent 用可编辑大纲产出预览，经确认后导出实际 PPTX，并回复带页级来源的产物。验收打开文件并核对内容。 |

设计回复交给通用助手，验证报告先回复代码会话，再随实现结果回到通用助手。PPTX 由已有的 PPT 会话直接回复通用助手。待审批可从主对话跳转到执行侧。发布目标完成时，宿主核对获确认的设计版本、实际应用的补丁、通过的测试和可打开的 PPTX 是否属于同一交付链。

### 回撤、方案比较与局部返工

| 情形 | 预期结果 |
| --- | --- |
| 回撤已应用的代码或设计变更 | 可查看反向补丁或恢复预览。按当前版本确认后，逐项核对实际恢复的资源，保留原操作和回撤记录。 |
| 目标已被用户改动、原写入部分完成或结果待核对 | 回撤计划展示可确定的范围。版本不匹配时保留用户改动并返回冲突。重启后以原调用和命令记录恢复，已处理的反向计划不会重复执行。 |
| 从同一需求分叉两种设计方案或 PPT 讲述方式 | 以相同输入版本分别生成候选。能并排查看版本、差异和验证证据。用户选中的版本进入主目标的准备和审批，主目标与未选中的候选维持各自状态。 |
| 选择候选后主目标变化 | 旧预览失效，按当前基线生成新的差异和审批，候选仍可查看。 |
| 测试报告中的一个结论更新 | 来源查询定位使用该结论的 PPT 页面。界面预览受影响范围，确认后以新来源重生成所选页面，核对结构化稿中其余页面的内容和稳定 ID。重新导出的 PPTX 可打开，旧版仍保留来源。 |
| 来源被撤回、片段关联缺失或再次变更 | 按权限显示不可用或扩大到产物级影响。新计划固定使用选定的来源版本。待执行计划的引用失效时重新核对计划及审批。 |
| 接入第三方 Agent | 外部宿主通过公开注册接口接入一个额外领域，使用同一 Runtime 和会话组件。通用助手能调用获授权的新增能力。访问未授权项目、工具或会话的请求按宿主策略返回，已注册的业务渲染器可展示结果。 |
| 通用助手使用 Skill 生成发布演示 | 在通用对话读取验证报告，再由用户选用或模型激活发布演示 Skill。按需加载同一版本的模板，沿用导出审批并检查可打开的 PPTX。重启可恢复原版本，撤销来源或访问越界时显示具体原因。 |

### 模型适配与自定义交互

| 情形 | 预期结果 |
| --- | --- |
| 同一任务分别经原生与兼容模型协议运行 | 文本增量、工具参数、调用 ID 及回传续轮符合统一契约。测试模型能力缺失、续轮状态边界、流中断和不同取消能力。 |
| 分别选择 `Ask`、`Auto Review` 和 `Full Access` | 验证手动确认、委托审查及其回退、授权范围内的免逐次确认。强制人审在各模式生效。覆盖领取队列前失效、写入前撤权、审查超时和重启后无有效决定。 |
| 模型生成可交互饼图 | 自定义渲染器呈现已校验的数据。筛选可在控件内完成，导出动作提交绑定的表单并经工具审批。旧版本和非法动作按契约反馈。 |
| 用户从会话入口启用、暂停和恢复 Goal | 状态和进展随目标快照更新，普通输入优先，待完成审核可跳转到所属会话。 |

### 协作与恢复用例

| 情形 | 预期结果 |
| --- | --- |
| Agent 创建会话并带初始任务，创建需批准或回执丢失 | 审批前可查询原命令。批准和重启后按同一命令 ID 取得会话、已登记的 Run 和初始请求 ID（如有）。目录中只有一个新会话，初始任务至多创建一个 Run。拒绝时任务不启动。新会话与发起 Run 的生命周期各自独立。 |
| 分叉时原会话还在运行或等待审批 | 分支从合法的已提交边界取得历史，能查看获准的来源，撤销来源权限后隐藏相应字段。原待审批记录和一次性批准仍由原会话处理。并行验收共享工作区的版本冲突和宿主分配的独立工作区。 |
| 通知、忙时排队、空闲唤醒和指定 Run 的补充输入 | 通知进入收件箱。排队请求在接收策略允许后只触发一次执行。补充输入在指定 Run 的安全边界应用，已结束的目标按受理时点返回 `AlreadyClosed` 或保留原投递的拒收结果。 |
| 接收方暂缓、拒收、权限撤销或引用失效 | 界面显示处理状态，接收方按最新授权取得数据。被拒绝或撤销的消息和产物按策略隐藏或报告不可用，相关写入仍由接收方审批。 |
| 先回复再等待、回复时发起方正等待或已取消 | 先回复可以直接读取；活动等待继续原 Run；已结束的等待保留状态且可查看迟到结果。回复不会阻塞在等待它的 Run 后面。 |
| 等待形成循环、接收方长时间忙或达到消息额度 | 区分新增等待失败与已登记等待结清，超时或超额返回明确状态，已有任务继续依其自身约束收尾。 |
| 重复投递、发送中崩溃、任务领取竞争和回复记录后崩溃 | 同一命令返回原回执。每条工作消息最多创建一个目标 Run，任务只有一个有效领取者。重建时能找到已提交的回复，未知写入仍需核对。 |
| 目标暂停、预算耗尽、依赖失败或证据校验失败 | 调度依对应状态停止，记录原因。恢复调度后，同一执行尝试最多启动一次。 |
| 目标证据通过，需要人审 | 主会话显示绑定目标修订和证据的完成审批。重启后可恢复该待办，批准后目标完成。拒绝、截止时间到期或证据换版后，旧审核无法完成目标。另验收配置为验证通过即完成的路径。 |
| 发布演示执行中从 10 页改为 5 页 | Goal 保留身份和用量。旧 10 页导出待办失效，已经开始的写入按原调用记录。独立验证会话完成后，其报告可供新条件复核。重启后从新定义推进并审批 5 页导出，旧完成审批无法完成新目标。 |
| 空闲会话转交，随后重新打开 | 目录更新当前助手，历史显示转交记录和获准的交接摘要。新 Run 使用新助手的策略，已有 Run 保留其原定义。活动根 Run 占用会话或绑定版本变化时返回相应错误。 |
| MCP 工具清单换版，同一轮调用多项工具 | 新清单从下一轮生效，旧调用和审批在版本不符时失效。仅明确允许且资源不冲突的调用可并行，审批与取消逐项生效，结果和原工具调用一一对应。 |
| 两个执行者同时领取、修改依赖形成环或旧结果抵达 | 领取只授予一个执行者。循环变更返回冲突及环路。过期尝试的结果保留为历史，当前执行尝试的结果继续作为任务状态的依据。 |
| 改版或撤回共享资料，两个会话同时引用一个项目产物 | 会话可追溯实际使用的版本。新的读取重新校验访问权和版本。发布冲突返回现有版本，待执行的操作引用失效时更新预览和审批。 |

确定性测试使用假模型、可控时钟和本地存储故障注入。覆盖读写事务的提交前后、队列消费、等待恢复、任务领取和项目共享项版本冲突。集成验收使用宿主实际提供的模型、权限策略、工作区和产物服务。

## 实施顺序

开工先验证现有 `HuxerUI::AgentKit` 及 `examples/preview` 的 SDK 消费构建。随后用假模型、假工具和可控时钟串起创建、订阅、流式消息、操作确认与取消。首个切片通过后再接入持久存储和两个业务助手，沿同一契约做重启及真实模型验收。

| 交付 | 主要内容 | 验收条件 |
| --- | --- | --- |
| 首版共用运行时与界面 | 内存会话、快照与命令、Run 状态、模型轮次、工具计划与审批、表单和产物扩展 | 假模型和工具可驱动同一个本地会话机制，覆盖重新挂载、重复提交、权限变化及取消 |
| 首版发布 | `SessionStore` 本地持久化及两条业务流程的检查点恢复，真实模型适配器，代码与 PPT 的宿主工具及界面 | 两个助手的端到端与共用用例通过，重启后能核对原审批、队列和产物版本 |
| 完整版本地执行与扩展 | 协作、任务及目标的持久化恢复，MCP、Skill 和子 Agent 调度 | 验证跨会话等待、项目与目标的重启恢复，以及工具目录更新、同轮工具调度、Skill、委派和父子取消 |
| 完整版 Preview 与项目协作 | 统一会话列表、新建对话时选择助手、通用助手直接调用与跨会话编排、目标、任务依赖、共享上下文和恢复 | 验证默认通用助手及三个专用助手的创建与切换，完成跨领域端到端验收和协作用例 |
| 完整版审阅与变更 | 回撤、候选并排审阅及应用、产物来源和局部返工 | 通过代码、设计和 PPT 产物的专项用例，验证第三方使用公开接口接入 |

## 后续规划

以下能力在有明确接入场景后再立项。

- **远端 Agent 与现有服务接入。** 当执行引擎需要运行在另一个进程或设备上时，再确定远端会话接口和传输方式。可用 HTTP/SSE 提供参考适配器，或按实际部署通过 SSH 承载应用协议。接入 AG-UI 时明确外部 Run 与库内 Run 的映射、交互恢复和能力差异。跨服务专家委派按需评估 A2A。 [AG-UI 交互恢复](https://docs.ag-ui.com/concepts/interrupts) · [A2A 任务与产物](https://a2a-protocol.org/latest/specification/)
- **跨设备接续与应用退出后的持续执行。** 由执行端持有权威 Run、待处理交互和产物引用。设备重新接入时读取一致快照、恢复订阅并查询未确认命令的结果。验收覆盖断线重放、多个设备同时提交表单，以及产物跨设备访问的授权。
